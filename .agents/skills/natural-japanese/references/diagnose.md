# 書き換えを伴わない診断

診断では原文を変更しない。自然度は「検出された癖が少ないほど高い」目安で、著者がAIかどうかを判定する数値ではない。

quickでは`japanese.ts score <file> --json`を実行し、見出しと段落冒頭を通読する。ジャンルが分かれば`--genre`を指定する。fullではoutline・termsも実行し、構造・読みやすさ・文書の型を確認する。診断のために推敲ループは回さない。

## 点数の内訳

機械ベースはCLIの`score.base`を使う。通常のfindingsだけで次の計算を行う。

```text
減点 = (critical × 8 + warn × 4 + info × 0.5) × 1000 / max(文書の文字数, 1000)
機械ベース = max(100 − 減点, 20)
```

文字数は改行・Markdownを含むUnicode文字数。小数第1位までを返す。解析対象の本文が100字未満なら`base`はnullで、数値を出さず短すぎる旨を伝える。本文が少ない議事録やスライドは、構造・内容について文章で診断する。`--reading-load`の指摘は式に含まない。

quickは機械ベースだけを使い、構造や意味を十分に評価していないと添える。fullはレビューの具体的な所見から±15点の範囲で判断調整し、最終値を0〜100に収める。文脈上適切な反復は減点を戻してよい。内訳と理由を必ず示し、採点のために同じ文書を何度も改稿しない。

| 点数 | 目安 |
| --- | --- |
| 90〜100 | 目立つ癖が少ない |
| 70〜89 | いくつか確認する箇所がある |
| 50〜69 | 表層や構造の修正を検討する |
| 0〜49 | 複数の強い指摘があり、内容に照らして優先順位を付ける |

この区分は推敲の目安であり、読者評価の実測値や確率ではない。

## 返すもの

1. 機械ベース・判断調整・最終点、または採点しない理由。
2. 優先度の高い理由3〜5件。実際の文と行番号を挙げ、読み手が困る点を説明する。
3. 直すなら何から着手するかを2〜3件。

指摘が少なければ項目数を埋めない。リライトの依頼があった場合にだけ原文を変更する。
