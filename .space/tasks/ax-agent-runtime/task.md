# 対話型エージェントと社内連携の設計

現在の段階：AX内Runtimeの初期無課金プレビューを実装し、実Keycloak・実AX・画面で質問→回答→本人限定成果物と実停止を確認した。成果物を [PR #18](https://github.com/sori883/agent-workspace/pull/18) にまとめた。工程・担当・受け入れ状況の正本は `implementation-orch/` の台帳。実装契約と確認順序は [implementation.md](implementation.md)。以下は設計と試作の履歴であり、「今回は設計まで」はその時点の範囲を示す。実AX・Webの新経路は、検証が揃うまで完成扱いにしない。

2026-10-07。基準はmain `a682948be9daddc37555067fd98475eb3938b427`。利用者はWebから依頼し、ローカルKubernetes上でスキル、サブエージェント、Python等の実行を使うエージェントを求めた。追加要件は社内API、MCP、RAGへの接続と、依頼者の本人性・権限に応じた閲覧・更新である。今回は設計まで。実装、環境変更、モデル呼出し、PR作成は行わない。

## 共通条件と現状

- 会話・実行・成果物は現在のWorkspace所属と本人ownerで非公開。Workspace owner/adminも他人の履歴を閲覧しない。Userは複数Workspace/Groupに所属し、admin/memberとgeneral/developerを分ける。
- React Router BFF → Hono共通API → app PostgreSQL → Go controller → AX/Substrate → Task内Python。APIにPython/ローカルファイル/Kubernetes操作を戻さない。DB配置はKubernetes外も許す。
- 1実行1Task、Taskは通常Podと同義と扱わない。AX/worker/Actorの配置と隔離保証を区別する。
- 現在のAntigravityアダプターはwrite_output一つ、subagents無効、builtin tools空、3モデル要求/2tool/90秒/成果物1件64KiB。API側の履歴から成功した会話を再構成し、実行環境の常駐には依存しない。
- 既知usage・実際の通信遮断/停止・成果物検証を揃えて終了する。開始の二重送信、未知usage時の続行、応答不明時の無条件再送をしない。全体同時実行枠は現在1件。
- 現在のモデル/SDKは最初の実装。将来のモデルプロバイダー差替えを妨げない。既存2,000円の費用条件は維持し、今回有料試験はしない。
- Web操作の拡張は今回設計を再開。定期実行の製品仕様は引き続き未確定。

- model上限2到達後のRESUMEで追加1要求とwrite_outputが発生し、「追加0要求」の期待が不合格。SDKのLIFETIMEだけで送信前予算を強制できない。
- 現行3 model/2 toolではファイルは生成したが最終理由が上限停止。構造化finishでは2 modelに減らせたが、finishもtool予算に入り累積2 toolで上限停止した。診断用application dispatchと製品の通常完了を分ける。
- post_tool_callからのcancelはtoolの副作用があってもDONE履歴を確認できず、その状態から再開しなかった。存在しない保存会話の拒否は追加送信0件、provider 503は1要求で停止した。

親はprobeコード・結果JSON・必要なローカル証拠を照合し、cancel時の未確定履歴を「副作用なし」と誤記しないよう補正を依頼した。SDK DB、cache、生の模擬要求はspike配下でGit除外し、手順・コード・要約結果だけを引渡し対象とする。
