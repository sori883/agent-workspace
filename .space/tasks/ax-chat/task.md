# AXで会話を続けるチャット画面

2026-10-06。基準 main `159fa7a`、ブランチ `codex/chat-workspace`。

利用者は、本番保存・認証の整備より先に、動作確認フォームからインタラクティブなチャット画面へ進みたいと希望した。エージェントも会話可能であることを説明し、実際に前の発言を踏まえて複数往復できるローカルチャットを作る。任意質問に利用者が「まずは、前の会話を踏まえて質問・相談を続けられる形」と回答し、短い文章会話を優先する方針を確定した。既存単発実行は保持する。

## 受け入れ条件

- C1: 新しい会話を作り、利用者とエージェントの発言を同じ画面で順に表示する。
- C2: 次の発言に保存済みの会話を渡し、再読込後も同じ会話を続けられる。
- C3: 返答待ち・失敗・受付不明を区別し、二重送信や再読込から新しい有料実行を勝手に始めない。
- C4: 既存AXの費用・使用量・終了処理の制御、Host/Origin/session/CSRFと入力/出力境界を維持する。
- C5: デジタル庁デザイン資料に沿って、狭い画面・キーボード・日本語入力で使える。画面で会話の流れと制限が分かる。
- C6: 会話履歴・実行・再送・停止を局所と実ブラウザで検証し、独立レビューとPRで引き渡す。

設計はdevlowの独立案A/Bを比較する。担当A/Bは読み取り専用、親が採用判断・記録・画面統合・実AX確認を持つ。費用上限2,000円とCLIの概算累計0.01 USD停止、モデル3要求・入力6000/出力512トークン・90秒・API再試行0は変更しない。保存先の本番化・共通ログイン・RAG・新規モデルはこの依頼から追加しない。
