# スキル自動読込の独立設計比較

2026-10-08。候補作成に参加していない比較担当による設計レビュー。対象は `design-candidates/automatic-skills/a.md`、`b.md` と、親担当から追加された「B の読込済み本文を不変 descriptor に格納する」統合案。実装・有料試験・実環境配備は未検証。

## 結論

**B を土台に採用し、下記条件を満たして descriptor 格納へ簡素化することを推奨する。** 両案ともモデルがメタデータを見て必要な本文を要求するため、意味に基づく自動選択を実現できる。ユーザーの要求は同じ Pod 内のツール呼出しまで Codex と一致させることではない。今回は既存の二操作・費用精算・実停止の境界を維持する価値が大きい。

| 基準 | A: 同じ Task 内のループ | B: 区間をまたぐ読込 |
| --- | --- | --- |
| 利用体験・選択精度 | 意味判断、明示指定、必要時の本文読込が可能。起動回数を抑えられる | 同じ選択方式を実現できる。読込ごとに Task の停止・起動が増える |
| 保存・認可・版 | 新しい可変操作列と各操作依存の記録が必要 | 不変 descriptor と確認済み区間を拡張できる |
| 費用・障害 | 全モデル操作の合算、連番、最終操作判定を SQL/Go/Python で作り直す | 一区間一モデル・一 tool の予約と精算を維持できる |
| 互換・配備 | 新 mailbox 版と旧版の二経路が必要 | 新 root 方針の条件分岐は必要だが mailbox は維持できる |

A の有用な点である、本文と補助ファイルの分離、厳密な公開版 ID、既読依存の再認可、明示指定を初回から適用する方針は B と整合する。A の可変 mailbox と全件探索ページ操作は今回取り込まない。B のカタログ省略件数の表示と slash による省略版の明示利用を残す。

## descriptor 格納案の採用条件

専用 chunk reader を新設せず、SQL が認可済みの主本文・補助ファイル一覧・選択済み補助本文だけを `skill_context` に投影する方式は妥当。既存 descriptor SHA が正確な転送内容を固定し、40 KiB 制限内の小さなテキストを扱う今回の範囲なら転送経路を増やす必要はない。ただし次を契約に含める。

1. **認可を空にしない。** 新 root の `definition_manifest=[]` は保存形の変更にすぎない。現行 `ax_workbench_live` は `ax_workbench_definitions` 経由で manifest の版を確認しているため、置換する場合は新しい依存確認が必要。descriptor に含めたカタログ情報と本文の全登録版を、Task への提供時とモデル送信直前に現在の本人・所属・公開状態で再認可する。廃止時に不変 descriptor を差し替えず停止する B の方針は、可用性上の不利益を記録すれば安全側の初期実装として成立する。
2. **新旧の厳密型を保つ。** 不変の discovery 方針がある新 root のみ `skill_context` を必須とし、旧 root の descriptor bytes/hash・版・既存 definition 転送を保つ。未知のキーを無条件に受け入れる変更にはしない。新規 `agent_version_id` の拒否より先に同一 idempotency key の受付再確認を扱う。
3. **コード Task へ本文を広げない。** Python 区間の descriptor には skill 本文を載せず、既存のコード・許可された入出力を維持する。資源 path は公開版内の完全一致で解決し、ファイルシステムパスや実行権限へ変換しない。
4. **上限超過と読込の失敗を成功にしない。** 完全な descriptor に対する 40 KiB と生成前の入力 6000 token を維持し、本文を黙って切らない。大きいスキル・補助ファイルが登録できても実行に使えない場合は、本文短縮など利用者が理解できる理由を返す。読込台帳への追記と次 descriptor 作成は同じ transaction とし、handoff 拒否が「スキル読込済みで完了」と見えないようにする。

これらは追加承認を要する新しい製品方針ではなく、今回の標準エージェント・自動読込を既存の境界内で成立させる必須条件である。

## 実装後の受け入れ証拠

- 初回モデルには候補メタデータだけ、read 後の区間には要求した本文だけ、補助本文は追加要求後だけ入る。明示指定は初回から入り、同名でも ID が混同されない。
- `read_skills` → 補助資料 → Python → 回答を既存の 6 モデル・8 tool・3 Python・9 区間・300 秒の枠内で通し、Task 起動を含む時間と費用を計測する。B の遅延は未計測であり、上限拡張で試験を通したことにはしない。
- 送信直前の失効、別 Workspace、他人の個人用、未読の補助ファイル、同じ読込の繰返しを拒否する。停止未確認・未知 usage から次区間へ進まない。
- 旧待機 root の回答、旧受付の再確認、旧 agent の履歴閲覧を維持する。通常 UI から選択・編集を外してもデータを破壊しない。
- slash のキーボード・IME・取消し・狭い画面と、スキル登録後の利用導線を確認する。preview は意味判断やスキル遵守の試験結果として表示しない。
