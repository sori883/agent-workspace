# 標準エージェントとスキル指定 UI

2026-10-08。担当: skills_ui。親の automatic-skills-contract.md に従う UI 単位。バックエンドの選択構造・認可・実行上限は親と各担当へ引き継ぐ。

## 変更した範囲

- 新しい依頼は標準エージェントに統一した。エージェントの選択とスキルのチェックボックスを削除し、通常は自動利用する説明を表示する。
- 入力欄の行頭 `/` から組み込み・登録スキルを絞り込み、明示指定を削除可能なチップへ保存する。登録版 UUID と組み込み ID を分け、合計8件までにする。候補には共有範囲と版を表示し、登録スキルの詳細を別タブで確認できる。
- ↑↓・Enter・Escape、IME の変換、Ctrl/⌘+Enter を分離した。未確定コマンドは送信前に止め、URL・複数セグメントの絶対パス・通常の割り算は本文として扱う。
- 一覧はスキルだけをページ送りで取得する。全本文の先読みは追加していない。`?skill=` の古い公開版指定を保持し、`?builtin=` を追加した。GET では実行しない。`?agent=` は終了した操作として説明し、標準エージェントへ案内する。
- 受付結果が不明なときは本文・チップを固定し、同じ送信内容で再確認する。外部送信への同意文は自動候補の名前・説明と読み込むスキル内容を含めた。候補省略数と実行失敗理由の表示を追加した。
- ライブラリとナビゲーションを「スキル」に整理した。旧エージェントの詳細は閲覧専用で残し、新規登録・コピー・編集・公開・利用終了・依頼選択の UI を終了した。保存済みデータと API は削除していない。
- スキル編集画面で、説明は自動選択の条件、指示は選択後に読む手順として記入例を示す。

所有ファイル: `web/app/routes/{workbench,library}.tsx`、`web/app/lib/library-page.server.ts`、`web/app/components/{definition-editor,workspace,skill-composer}.tsx`、`web/app/app.css`、`web/tests/browser/{workbench,library}.spec.ts`。共有型・SQL・Runtime・Go は他担当の変更を利用する。

## 根拠と確認

devlow の本文・全体フロー・実装工程、use-principles、OKF、DADS スキルを確認した。親が確認済みのルール・原則と DADS 20260909 の layout / textarea / menu-list-box を引き継ぎ、`web/app` の code_refs から `knowledge/ax-web-foundation` の本人限定・現在所属・GET 非実行・再送固定を照合した。既存フォームの色・余白・フォーカス表示を使う。デザインシステムや WCAG の完全適合は主張しない。

型検査と production build は成功した。ブラウザは13種類の試験を確認済み。チップの詳細リンクを含む最新 UI で12件が合格し、52個の登録スキルを使うページ送り・自動候補省略表示の追加1件も単独実行で合格した。候補の件数を理由にスキル本文を先読みしない。

確認中に発生したテスト側の失敗: 初回の非実行ブラウザ2件では旧エージェント閲覧専用が合格し、組み込みの利用リンク1件が accessible name の空白差で失敗したため、リンク名のテスト指定を修正した。ページ送りの初回では試験 helper がログイン時の workspace を保持しているのに新しい workspace へ切り替えたと想定していたため、試験 URL を対象 workspace の明示指定へ直した。どちらも修正後の同じ確認経路で成功した。

実行: `npm run typecheck`、`npm run build`、`npm run test:e2e -- tests/browser/workbench.spec.ts tests/browser/library.spec.ts`（最終12件合格、上記ページ送り1件のみ試験修正が必要）、`npm run test:e2e -- tests/browser/workbench.spec.ts -g 'slash pagination'`（修正後1件合格）。

画面証拠は `evidence/automatic-skills-*.png` に保存し、既存 `general-*` の受け入れ済み証拠を上書きしていない。320px のスラッシュ候補画面を目視し、はみ出しがないことを確認した。ブラウザ検証は専用ポート3210/3211と試験DBの fixture を使用し、実モデル呼び出しは行っていない。3100のサービス再起動・PR・コミット・公開は担当範囲外。

## 引き継ぎ

自動的なスキル読み込みの実挙動・最新コードでの配備・有料モデルによる確認は親の統合検証へ渡す。UI 試験の fixture 成功を実モデルへの適用成功とは扱わない。新しい単一セグメントの `/name` はスキルコマンドとして解釈するため、同じ形式を文字列として相談する場合は引用符を付けるなどの区別が必要。

## 独立レビュー後の最終確認

P2の公開版内容確認の不一致を修正した。候補と選択済みチップは`?version=<公開版UUID>`へリンクし、詳細画面はgetVersionで再認可・definition_idを照合した対象版だけを表示する。下書きと編集・公開・コピー操作は含めない。v2公開・下書き改名後でも、v1チップからv1本文だけを確認する回帰を追加した。

修正後、型検査・build・workbench/libraryのブラウザ13件を一括で再実行して全件成功（24.3秒）。独立レビュー担当Bも修正差分を読み返し、指摘の解消を確認した。これは上記12件＋1件の確認後に行った最終検証である。
